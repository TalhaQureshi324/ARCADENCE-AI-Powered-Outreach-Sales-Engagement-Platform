# Phase 14.1 — Architecture, Security and Backend Audit Report

**Auditor:** Principal software auditor and release engineer
**Baseline:** commit `78763d1` (main), audit branch `audit/phase-14-remediation`
**Scope:** Scala domain modules, all API routes and permission checks, Supabase
JWT validation, tenant isolation, RLS policies for every tenant-owned table,
migrations, credential encryption, API keys and webhook signatures, AI agent
permissions, data export/deletion, Stripe idempotency, sending-engine
transaction boundaries, tracked-file review.

---

## Method

1. Schema-wide RLS audit executed against the live local database via
   `pg_tables`/`pg_class`/`pg_policies` (every regular table in `public`,
   not just the 8 tables the CI previously checked).
2. PostgREST exposure check: `information_schema.role_table_grants` for
   `anon`/`authenticated` on every table found without RLS.
3. Tracked-file review: `git ls-files` scan for archives, logs, env files,
   secret-named files; content inspection of flagged artifacts.
4. Route auth coverage: per-file endpoint vs auth-gate count across all 20
   route classes; manual review of intentionally public endpoints.
5. Webhook signature verification reviewed (Stripe + Arcadence format).
6. Full regression suite executed against the database.

---

## Findings

### CRITICAL

**C-1. Twelve tables with RLS disabled and full anon/authenticated grants
(cross-tenant exposure via PostgREST).**

Evidence: `pg_tables`/`pg_class` audit found `rowsecurity = false` on:
`campaign_daily_stats`, `campaign_event`, `crm_task_assignment`, `event_outbox`,
`inbound_events`, `job_attempt`, `job_queue`, `mailbox_sync_cursors`,
`provider_message_refs`, `quota_reservation`, `send_attempt`, `sync_jobs`.
`information_schema.role_table_grants` confirmed `anon` and `authenticated`
hold SELECT/INSERT/UPDATE/DELETE on them (Supabase default privileges).

Impact: any authenticated Supabase user could read delivery evidence
(`send_attempt`), campaign events, and job internals across ALL workspaces
via PostgREST, bypassing the Scala API's permission checks entirely.

This directly confirms the reviewer's Finding C: the CI check verified only
8 hardcoded foundational tables, so these 12 were never caught.

**FIX APPLIED:** migration `20261103110000_rls_hardening.sql` enables RLS on
all 12 tables with no policies — deny-by-default for PostgREST. The Scala
API and worker connect as the database owner and bypass RLS, so application
behavior is unchanged (full regression suite green; see Tests section).
Commit: see git log on this branch.

**C-2. CI RLS verification was not schema-wide.**

Evidence: `.github/workflows/ci.yml` "Verify foundational schema + RLS" step
checked `relname in ('profile','organization','workspace',...)` — 8 names.

**FIX APPLIED:** the CI step now asserts schema-wide that **every** regular
table in `public` has RLS enabled (fails on any exception), plus a second
assertion that every RLS-enabled table has at least one policy unless it is
on an explicit deny-by-default allowlist. This turns the reviewer's Finding C
into a permanently enforced gate.

### HIGH

**H-1. `scala-log.zip` tracked at repository root.**

Evidence: `git ls-files` includes it; content inspection shows it is a
120-byte GitHub REST API 401 JSON error (`"Requires authentication"`) saved
with a .zip extension — **no secrets inside**. It is a leftover artifact from
an early scripted GitHub API call that lacked auth.

Status: **no credential exposure**, but it is noise and confused the external
reviewer. Removed from tracking in the remediation commit (file kept locally
via .gitignore entry).

### MEDIUM

**M-1. Local `EMAIL_ENCRYPTION_KEY` loss and replacement (documented).**
Evidence: HANDOFF.md Phase 11 addendum. Impact: email-account credentials
encrypted before 2026-11-01 must be reconnected locally. Production/staging
keys are separate (owner-generated). Action for owner: store the production
key in a secret manager with backup (MANUAL_SETUP row exists).

**M-2. `env.local` values were not committed.** Verified: only
`apps/api/.env.example` and `apps/worker/.env.example` are tracked, both
placeholders. No `.env.local` in the index (checked `git ls-files` and
`git check-ignore`).

**M-3. Deny-by-default posture tables.** `account_credentials` (encrypted
credential blobs) and `billing_events` have RLS enabled with zero policies —
intentional: PostgREST cannot read them at all; the Scala API bypasses RLS.
Documented in the CI allowlist so the policy-coverage assertion does not
false-positive.

### LOW

**L-1. `DocsRoutes` is intentionally public** (OpenAPI spec + developer
guide, no tenant data). Documented, not a finding requiring change.

**L-2. Route auth coverage is complete.** Audited counts per route file
(endpoints vs auth-gate references): every serverLogic block in every
workspace-scoped route passes through `requireEdit`/`requireView`/
`requireManage` before any data access. Intentionally public endpoints:
Stripe webhook (HMAC signature-verified), `/track.js` + event collection
(site-key gated), `/openapi.json`, `/developers`. No unauthorized access found.

**L-3. Stripe webhook idempotency verified.** `billing_events` unique on
`stripe_event_id`; duplicate delivery returns `duplicate: true` with no
double-apply (BillingSpec 4/4). Signature format `t=…,v1=…` matches Stripe.

**L-4. Sending-engine transaction boundaries unchanged** by this audit;
sending remains deterministic and AI-independent (Phase 5/13 findings).

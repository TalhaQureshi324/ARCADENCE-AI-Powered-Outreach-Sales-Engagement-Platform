# Phase 14.4 — Resilience, Operational Readiness and Recovery (Evidence Report)

**Branch:** `feature/phase-143-144-verification`
**Executed:** 2026-11-09 against the real database (local Supabase stack).

## 1. Worker concurrency, leasing, idempotency, duplicates

Verified by WorkerQueueIntegrationSpec (executed in isolation: **6/6 green**):
- 6 concurrent workers × concurrent drain: zero double-claims (SKIP LOCKED).
- Expired leases: jobs return to pending and are re-claimed exactly once.
- Retry/backoff: failures back off with capped exponential + jitter until
  max_attempts, then dead-letter.
- Database reconnection: operations resume on a fresh transactor after
  interruption.
- Application-level idempotency keys make duplicate enqueue a no-op.

Measured throughput (ReliabilityLoadSpec, isolated): enqueued 20 in 1490ms,
drained 20 in 2608ms — **4.9 jobs/s end-to-end** including per-send evidence
writes. This is a local-harness measurement, not production capacity.

## 2. Quotas and sender affinity

- Atomic `quota_reservation` row-locks the daily counter (Phase 5.2 spec:
  simultaneous reservation race won by exactly one worker).
- Sender affinity: allocation prefers the conversation's last sender
  (SchedulerIntegrationSpec).
- Per-account circuit breaker: 3 auth failures suspend the account; worker
  defers jobs for suspended accounts (SendDeliverySpec).

## 3. Unknown-outcome reconciliation

Ambiguous submissions are held (status `held`) and never retried blind
(ADR-0030). **Safe automation recommendation:** for SMTP providers, a
`search` by Message-ID on the delivery folder can resolve held outcomes
automatically; for Gmail/Graph, a history/message-get call can do the same.
Recommended as a Phase 14 follow-up WITH a per-provider allowlist and a
max-resolution-age cap; requires no new credentials (reuses connected
account tokens).

## 4. Load testing (measured, local harness)

- Concurrent drain: 6 workers, zero duplicates (isolated run 6/6).
- Combined-run caveat: WorkerQueue sleep-based assertions flake under
  full-suite parallel load (2/6 failures observed twice) — green 6/6
  isolated. **Tracked hardening item: serialize the spec.**
- ReliabilityLoadSpec 3/3 isolated.
- Production-scale load testing: NOT performed (requires production-size
  data + staging infrastructure). No theoretical capacity is claimed.

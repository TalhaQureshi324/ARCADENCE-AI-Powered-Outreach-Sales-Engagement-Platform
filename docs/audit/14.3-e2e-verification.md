## Known timing limitation (documented)

WorkerQueueIntegrationSpec contains sleep-based assertions that flake when the
full suite runs in parallel (2 of 6 failed in one combined run; 6/6 green in
the isolated run immediately after, twice reproduced). Serialization of that
spec is a tracked hardening item. ReliabilityLoadSpec: 3/3; measured local
throughput ~4.9–8 jobs/s end-to-end on the test harness.

## Remaining 14.3 gap

A single consolidated journey spec chaining all 18 stages in one test would
improve regression ergonomics; today the chain is proven by the union of the
per-link suites above (each executed and green against the real database).
Scheduled as follow-up work alongside the WorkerQueue serialization fix.
